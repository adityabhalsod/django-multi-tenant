# 3. Python and dependencies with uv

[uv](https://docs.astral.sh/uv/) replaces `pip`, `pip-tools`, `virtualenv` and `pyenv` with one
fast tool. This project uses it everywhere: on your laptop, in CI and in the Docker image.

## 3.1 Install uv

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
# or: brew install uv / pipx install uv
```

## 3.2 The files uv uses

| File | Purpose |
|---|---|
| `pyproject.toml` | Declares dependencies (`[project.dependencies]`), optional extras (`s3`, `sentry`) and the `dev` dependency group. |
| `uv.lock` | Exact, cross-platform pinned versions. **Commit it.** CI and Docker install with `--locked`. |
| `.python-version` | The Python version uv installs and uses (3.13). |
| `.venv/` | The virtual environment uv creates. Never commit it. |

`[tool.uv] package = false` tells uv this is an application, not a library to build.

## 3.3 Everyday commands

```bash
uv sync                          # install everything (runtime + dev group) exactly as locked
uv sync --no-dev                 # runtime deps only (what production uses)
uv sync --extra s3 --extra sentry  # include optional extras
uv run python manage.py shell    # run anything inside the venv, no "activate" needed
uv run pytest -k isolation       # run tests

uv add django-filter             # add a runtime dependency (updates pyproject + lock)
uv add --dev pytest-xdist        # add a dev-only dependency
uv add --optional s3 boto3       # add to an optional extra
uv remove django-filter          # remove it again

uv lock --upgrade-package django # upgrade one package within its constraints
uv lock --upgrade                # upgrade everything
uv tree                          # show the dependency tree
uv python install 3.14           # install another interpreter
```

## 3.4 How Docker uses uv

The `Dockerfile` copies the `uv` binary from the official image and installs dependencies in
a separate, cached layer:

```dockerfile
RUN --mount=type=cache,target=/root/.cache/uv \
    --mount=type=bind,source=uv.lock,target=uv.lock \
    --mount=type=bind,source=pyproject.toml,target=pyproject.toml \
    uv sync --locked --no-dev --no-install-project
```

* `--locked` fails the build if `uv.lock` is out of date, so images always match the lock.
* `--no-install-project` installs dependencies only, so changing your code does not
  invalidate the dependency layer.
* The venv lives in `/opt/venv` (`UV_PROJECT_ENVIRONMENT`), outside `/app`, so bind-mounting
  your source in development does not hide it.
* Build with optional extras: `docker build --build-arg UV_EXTRAS="--extra s3" .`

## 3.5 Pre-commit hooks

```bash
uv run pre-commit install        # once; ruff + basic checks run on every commit
uv run pre-commit run --all-files
```
